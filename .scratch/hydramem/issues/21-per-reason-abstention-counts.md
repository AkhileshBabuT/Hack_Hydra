# 21 — Per-reason abstention counts, generated rather than derived

> *This was generated by AI during triage.*

Status: ready-for-agent

## Parent

`.scratch/hydramem/PRD-appeal.md`

## Why this exists

`docs/eval/` reports `abstain_precision` and `abstain_recall` and nothing about
*why* an abstention happened. So the headline reads "HydraMem abstains a lot",
when the truth is that it abstains for four distinguishable causes in very
uneven proportions, and three of the four are false abstentions caused by
different bugs needing different fixes.

The breakdown was computed by hand from `.eval/oracle/hydramem.jsonl` during the
2026-08-16 grill session:

| reason | n |
|---|---|
| `not_in_graph` | 27 |
| `no_such_relation` | 16 |
| `unknown_entity` | 15 |
| `no_fact_in_window` | 2 |
| `no_path` | 0 |
| `fabricated_citation`, `uncited_answer` | 0 |

**Those numbers are not quotable and must not be cited anywhere until this issue
closes.** CLAUDE.md's rule is that a number not generated into `docs/eval/` does
not exist, and a table computed in a chat session is exactly what that rule is
for. Issue 22 claims a delta against `not_in_graph`; it cannot until this lands.

Two of the rows are findings in their own right and neither is currently written
down:

- **`no_path` is 0.** Gate 4 does not fire once across the whole slice, while
  still costing a round trip on multi-entity questions. CLAUDE.md calls it "close
  to vacuous"; this makes it exact.
- **`fabricated_citation` and `uncited_answer` are both 0.** Gate 5 — the
  strictest thing in the cascade, and the part most likely to be read as
  over-engineering — throws away **nothing**. That is a good result the
  submission does not currently claim.

## What to build

Abstention counts broken out by reason code, as generated columns alongside the
existing rates, per arm and per category, with the true/false split.

Each reason needs both totals: how many abstentions carried it, and how many of
those were on questions with a gold answer. An abstention count without the
false half is the number that makes recall look like a virtue on its own.

The breakdown is derived from the per-question resume log the harness already
writes, so this costs no NIM calls, no round trips, and no re-scoring. It must be
rebuildable with the existing summarise-only path — regenerating this table must
never require scoring a question.

Baseline arms record no reason codes, since they have no gates. Their rows should
say so explicitly rather than showing zeros, because a zero reads as "this never
happened" and the truth is "this cannot happen here".

## Acceptance criteria

- [ ] Abstention counts appear per reason code in the generated `docs/eval/`
      output, per arm and per category
- [ ] Each reason carries its true/false split, not just a total
- [ ] The per-reason counts sum to the arm's total abstention count — asserted by
      a test, so a new reason code cannot be silently dropped from the breakdown
- [ ] The table regenerates from the existing resume log with no scoring, no NIM
      calls and no Bolt round trips
- [ ] Arms with no gates are distinguishable from arms with gates that never
      fired
- [ ] `docs/eval/oracle-results.md` carries the breakdown in prose, so the four
      causes are visible without opening a CSV
- [ ] CLAUDE.md records `no_path = 0` and `fabricated_citation = 0` as measured,
      in the gate 4 and gate 5 sections
- [ ] Tested in `tests/test_eval.py` over plain row dicts — no driver, no model,
      passes with Docker down
