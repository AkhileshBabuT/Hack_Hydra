# Out of scope — LongMemEval-V2 and BEAM

> *This was generated by AI during triage.*

Proposed by `hydramem-verification-cascade.md` §8.2 and §8.3. Declined
2026-08-16. Recorded so the proposal is not made again without new information.

## What was proposed

Three benchmarks, three harnesses: LongMemEval (built), LongMemEval-V2 (451
questions over web-agent trajectories, up to 115M tokens), and BEAM-100K (20
dialogues, 400 questions, rubric-nugget partial credit).

## Why declined

Not because the benchmarks are bad — because each one is a **new ingest path, a
new judge, and a schema migration**, and this repo's schema additions are
migrations rather than backfills.

- **V2 needs `:Action` and `:Observation` node labels.** CLAUDE.md caps the
  design at 6 edge types because CSC generations are built per edge type. Adding
  two labels plus their edges is a graph-shape change, not a loader change.
- **A schema addition here requires a wipe.** `UPSERT_ENTITY` is guarded on
  `last_seen`, and the guard comparison is strictly less-than, so an equal guard
  value writes nothing. `skey` proved this in slice 17: adding one property broke
  every caller at parse time and needed a full wipe and re-ingest. Two new labels
  is that cost, twice.
- **BEAM's rubric-nugget judge is not comparable to LongMemEval's binary judge.**
  The doc says so itself. Two incomparable scoring systems in one submission
  invite exactly the averaging mistake CLAUDE.md forbids.
- **The measured bottleneck is not coverage.** 60 of 150 questions are false
  abstentions on the benchmark already built. A second benchmark measures the
  same defect again in a new place rather than fixing it.
- The doc's own §8.4 says: *"If only three cycles are available: run 1, 2, 3 and
  report V2/BEAM as scoped-out with the adapter design documented. A working
  LongMemEval result with an honest per-category table beats three half-finished
  benchmarks."* This is that decision.

## What would reverse it

- The 27 `not_in_graph` false abstentions are closed **and** `_s` is scored, with
  cycles left over.
- Or a claim is needed that LongMemEval alone cannot support — specifically
  **contradiction resolution** or **event ordering**, which only BEAM tests and
  which nobody has solved. If those become the headline, BEAM-100K is the only
  place to measure them, and it is worth its cost then.

## What survives

The adapter *designs*, not the runs. `docs/architecture.md` should carry a short
section saying how each would attach if picked up:

- **V2** — trajectory-step extraction windows instead of session windows; one
  extraction call per action-observation block; dynamic state tracking is already
  a SUPERSEDES chain, so gate 3 needs no change. Premise awareness is the
  abstention analogue and maps onto the existing reason codes.
- **BEAM** — contradiction resolution is two non-superseded facts asserting
  conflicting values for one predicate, which `chain.group_key` can already
  detect without a model. Event ordering is an ORDER mode over `valid_from`.
  Both are cheap *given the loader*; the loader is the cost.
